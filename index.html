🚀 Welcome to Java OOP

Object-Oriented Programming (OOP) is a way of writing code that mirrors how we think about the real world. Instead of writing long lists of instructions, we organize our code into "objects" that represent real things—like a Dog, a Car, or a Person.

Why Learn OOP?

✅ Organized: Code is grouped logically, making it easier to understand and maintain

✅ Reusable: Write code once, use it many times

✅ Flexible: Easy to add new features without breaking existing code

✅ Real-world: Models real objects and their relationships

The Four Pillars of OOP

Think of building a house:

1. Classes & Objects - The blueprint (class) and the actual house (object)

2. Encapsulation - Hiding internal wiring, keeping some things private

3. Inheritance - A penthouse is a special kind of house, inheriting house features

4. Polymorphism - Different actions for different types (apartment vs. house)

📦 Classes and Objects

A Class is like a blueprint or template. An Object is an actual thing created from that blueprint.

Real-World Analogy

Think of a cookie cutter (the class) and cookies (the objects):

  • The cookie cutter is the class—it defines the shape
  • Each cookie you make is an object—each one is a real, edible thing
  • You can make many cookies from one cutter

Creating a Class

Here's a simple Java class representing a Dog:

public class Dog { // Properties (what the dog HAS) public String name; public String breed; public int age; // Constructor (how to create a dog) public Dog(String name, String breed, int age) { this.name = name; this.breed = breed; this.age = age; } // Methods (what the dog CAN DO) public void bark() { System.out.println(name + " says: Woof! Woof!"); } public void eat() { System.out.println(name + " is eating..."); } }
📋 Class Components
Component Purpose Example
Properties What the object HAS (characteristics) name, breed, age
Constructor Creates a new object Dog("Buddy", "Golden Retriever", 3)
Methods What the object CAN DO (actions) bark(), eat()

Creating Objects (Instances)

Now let's create actual objects from our Dog class:

// Creating object 1 Dog dog1 = new Dog("Buddy", "Golden Retriever", 3); // Creating object 2 Dog dog2 = new Dog("Max", "German Shepherd", 5); // Using the objects dog1.bark(); // Output: Buddy says: Woof! Woof! dog2.eat(); // Output: Max is eating...
💡 Key Insight: The class is the template, but objects are real things with real values. dog1 and dog2 are different objects with different properties!

🔒 Encapsulation

Encapsulation means hiding the internal details of an object and only letting people use what they need. It's like a car—you use the steering wheel and pedals, but you don't need to know how the engine works inside.

Without Encapsulation (❌ Bad)

Everything is public—anyone can change anything:

public class BankAccount { public double balance; // ⚠️ Anyone can change this! } // Bad: Anyone can change the balance! account.balance = -1000; // Oops! Negative balance!

With Encapsulation (✅ Good)

Hide the details, provide controlled access:

public class BankAccount { private double balance; // Hidden! Can't access directly // Constructor public BankAccount(double initialBalance) { this.balance = initialBalance; } // Getter: Read the balance safely public double getBalance() { return balance; } // Setter: Change balance safely with validation public void deposit(double amount) { if (amount > 0) { balance += amount; } } }
💡 Access Modifiers:
  • public - Anyone can access
  • private - Only the class can access
  • protected - Class and subclasses can access

👨‍👧 Inheritance

Inheritance lets you create a new class based on an existing class. The new class inherits all the properties and methods of the parent class, and can add its own special features.

Real-World Example

Think of vehicles:

  • Vehicle (parent) - has wheels, engine, color
  • Car (child) - inherits from Vehicle, adds doors, trunk
  • Truck (child) - inherits from Vehicle, adds cargo bed
🚗 Vehicle
↓ ↓ ↓
🚙 Car
🚚 Truck
🏍️ Motorcycle

Parent Class (Superclass)

The parent class that others will inherit from:

public class Animal { protected String name; protected int age; public Animal(String name, int age) { this.name = name; this.age = age; } public void sleep() { System.out.println(name + " is sleeping..."); } }

Child Class (Subclass)

The child class inherits from Animal using extends:

public class Dog extends Animal { private String breed; public Dog(String name, int age, String breed) { super(name, age); // Call parent constructor this.breed = breed; } // New method for Dog public void bark() { System.out.println(name + " says: Woof!"); } } public class Cat extends Animal { public void meow() { System.out.println(name + " says: Meow!"); } }
💡 What's Inherited? Dog and Cat automatically get: name, age, and sleep() method from Animal. They can add their own methods too!

🎭 Polymorphism

Polymorphism means "many forms". The same method name can do different things for different objects. For example, all animals can "makeSound()" but each makes a different sound!

Real-World Example

Imagine a "makeSound()" instruction:

  • Dog → Woof!
  • Cat → Meow!
  • Cow → Moo!

Same method, different results!

How It Works: Method Overriding

The parent class defines a method, and child classes provide their own version:

public class Animal { public void makeSound() { System.out.println("Some generic sound"); } } public class Dog extends Animal { @Override public void makeSound() { System.out.println("Woof! Woof!"); } } public class Cat extends Animal { @Override public void makeSound() { System.out.println("Meow!"); } }

Using Polymorphism

Here's the magic—you can treat all animals the same way:

// Create a list of animals Animal[] animals = new Animal[3]; animals[0] = new Dog(); animals[1] = new Cat(); animals[2] = new Cow(); // Call makeSound on each animal for (Animal animal : animals) { animal.makeSound(); // Each makes its own sound! }
💡 Power of Polymorphism: Write once, work with many types! You don't need to know the exact type of animal to call its method.

🎨 Abstraction

Abstraction means hiding complexity and showing only what's necessary. You define what an object SHOULD do (an interface or abstract class), but don't specify exactly HOW to do it.

Real-World Example

Think of a remote control:

  • You see: Power button, Volume button, Channel buttons
  • You don't see: Complex circuits, how it actually works
  • You don't need to know the details to use it!

Abstract Class

An abstract class is like a blueprint that child classes must follow:

public abstract class Shape { // Abstract method - must be implemented by child classes public abstract void draw(); public abstract double calculateArea(); // Concrete method - same for all shapes public void display() { System.out.println("Displaying shape..."); } }

Concrete Implementation

Child classes MUST implement abstract methods:

public class Circle extends Shape { private double radius; public Circle(double radius) { this.radius = radius; } @Override public void draw() { System.out.println("Drawing a circle..."); } @Override public double calculateArea() { return 3.14 * radius * radius; } } public class Rectangle extends Shape { private double width, height; public Rectangle(double width, double height) { this.width = width; this.height = height; } @Override public void draw() { System.out.println("Drawing a rectangle..."); } @Override public double calculateArea() { return width * height; } }
💡 Why Abstraction?
  • Forces consistent structure across classes
  • Hides implementation complexity
  • Makes code flexible and extensible
